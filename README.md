A project that predicts telecom customer churn with a PyTorch MLP neural network, benchmarked against Scikit-Learn baselines, with experiment tracking in MLflow and an inference API built with FastAPI.

## Context

A telecom operator is losing customers at an accelerating rate. Leadership requested a predictive model that flags customers at risk of cancelling, to support retention actions.

The project covers the full workflow: problem definition, exploratory analysis, model training, results comparison, pipeline packaging, inference API, tests, and final documentation.

## Dataset

The suggested dataset is a public telecom churn dataset, such as Telco Customer Churn. The final source, data dictionary, and data-handling decisions will be documented during the EDA stage.

## Metrics

Technical metrics used:

- ROC-AUC
- F1-score
- Precision
- Recall
- Confusion matrix

Planned business metrics:

- Estimated cost of a false positive.
- Estimated cost of a false negative.
- Estimate of churn avoided.
- Trade-off comparison between retaining customers and avoiding unnecessary campaigns.

## Baseline Results

Model: Logistic Regression with `class_weight="balanced"`.

| Metric | Value |
| --- | ---: |
| Accuracy | 0.726 |
| ROC-AUC | 0.835 |
| F1 | 0.607 |
| Precision | 0.490 |
| Recall | 0.797 |

The baseline identifies about 79.7% of the customers who actually churned in the test set. This result serves as the reference for comparison with the MLP.

## MLP Results

Model: PyTorch MLP with two hidden layers, dropout, positive-class weighting, and early stopping.

| Metric | Value |
| --- | ---: |
| ROC-AUC | 0.835 |
| F1 | 0.612 |
| Precision | 0.501 |
| Recall | 0.786 |

The MLP is very close to Logistic Regression on ROC-AUC, with slightly higher F1 and precision but slightly lower recall. For the retention goal, Logistic Regression remains a strong choice for the API: it is simple, interpretable, and has marginally higher recall.

## Setup

Create and activate a virtual environment:

```bash
python -m venv .venv
.venv\Scripts\activate
```

Install the project with development dependencies:

```bash
pip install -e ".[dev]"
```

On Windows with CPU only, the validated PyTorch version was:

```bash
pip install torch==2.5.1+cpu --index-url https://download.pytorch.org/whl/cpu
```

## How to Reproduce

Clone the repository:

```bash
git clone https://github.com/andreluizpedroso/telco-churn-mlops.git
cd telco-churn-mlops
```

Create the virtual environment and install the dependencies:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"
```

Set the package path in PowerShell:

```bash
$env:PYTHONPATH="src"
```

Download the public Telco Customer Churn dataset:

```bash
python scripts/download_data.py
```

The file will be saved locally at:

```text
data/raw/Telco-Customer-Churn.csv
```

Generate the processed data and the baseline metrics:

```bash
python -m telco_churn_mlops.baselines
```

If MLflow is installed, this command also logs parameters, metrics, and artifacts to the `telco-churn-mlops` experiment.

Generate the artifact used by the API:

```bash
python -m telco_churn_mlops.train_baseline_model
```

Start the API:

```bash
uvicorn telco_churn_mlops.api:app --reload
```

Open:

```text
http://127.0.0.1:8000/health
http://127.0.0.1:8000/docs
```

To reproduce the charts, open and run:

```text
notebooks/01_eda_baselines.ipynb
```

```bash
python -m telco_churn_mlops.train_baseline_model
```

```bash
$env:PYTHONPATH="src"
python -m telco_churn_mlops.train_mlp
```

This command generates local artifacts in `models/` and logs the run to MLflow when the dependency is available.
